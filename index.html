Sine, cosine and angles from nothing but shifts and adds.

tt_um_aariv_cordic_alu is a small Tiny Tapeout design for the GF180MCU shuttle. One eight clock CORDIC engine rotates and measures vectors. Next to it sit a saturating accumulator and a pseudo random generator with a CRC. This page runs the same logic in your browser, one clock edge at a time.

    How the datapath works

    CORDIC turns a rotation into a staircase of tiny, fixed turns. Each turn is a shift and an add, so the chip never needs a multiplier.

    The engine keeps three registers. x and y hold a vector, and z holds the angle still left to turn. On stage i the vector turns by plus or minus atan(2^-i). A turn of that size equals x shifted right by i bits, added to or taken from y, and the other way round for x. A small lookup table holds the eight angles.

    In rotation mode the sign of z picks the turn direction, and z shrinks toward zero. Starting from x = 0.607 cancels the length growth of 1.6467 that the eight turns add, so the result is cosine in x and sine in y.

    In vectoring mode the sign of y picks the direction and the engine drives y to zero. Then z holds the angle of the input and x holds its length times 1.6467. A vector in the left half plane is first turned by 90 degrees so the loop converges.

    Measured accuracy

    These figures are recomputed in this browser from the simulator every time the page loads, against Math.cos, Math.sin and Math.atan2.

    Worst cosine error
    1.73 LSB
    Worst sine error
    1.45 LSB
    Worst length error
    1.07 counts
    Worst angle error, length 8 or more
    1.15 counts

    One LSB is 1/128, about 0.8 percent of full scale. One angle count is 1.4 degrees. Vectors shorter than 4 units lose precision because the registers hold only 3 fractional bits there, with errors up to about 6 counts.

    What has been checked, and what has not

    Done

    • The Verilog compiles clean under Icarus Verilog 13 with warnings on, and synthesizes in Yosys 0.70.
    • A replay bench runs the Verilog and this page's JavaScript twin through the same stimulus. Every output and every internal register matched after every clock edge for 320,028 cycles, over two random seeds plus directed sweeps of every operation.
    • The comparison was shown to fail when either side is changed by one constant, so a pass means something.
    • Accuracy limits above are asserted by the test suite, not only displayed.

    Not done

    • No tapeout. No GF180MCU place and route has been run, so the tile fit and the real standard cell count are unknown.
    • No test on an FPGA or with a logic analyzer. The plan is to load the Verilog on an FPGA board, wire ui_in and uio_in to switches, and capture uo_out and uio_out on a logic analyzer while stepping through the four operations in the table above.
    • The Tiny Tapeout GitHub workflows (test, gds, docs, fpga) have not run yet, because the repository has not been pushed. The cocotb tests in test/test.py pass locally under Icarus Verilog, and they check against math rather than the JavaScript twin.
    • No write up has been published. WRITEUP.md only collects measured facts for a person to write from.
